# Ordinary reasoning profiles: separate prospective development screen

The earlier [frontload development screen](frontload-development-2026-11-14.md)
stopped after seven requests when `ClientOSError` affected self-review. It did
not yield a complete five-task ranking or a holdout candidate. On its one
exposed Boolean task, both 4096 and 8192 drafts spent every completion token
on hidden reasoning and emitted no answer. This separate screen uses new
questions to test whether an explicit ordinary reasoning profile can make a
terminal answer available within the original 4096 stage cap. The previously
observed numeric error with low effort is an adverse prior result, so output
availability alone is not a success criterion. Do not repeat the stopped
questions or alter their scores. A replay bridge for the observed aiohttp
transport error is an offline harness correction, not a retroactive success
for that failed replay.

Freeze this protocol, source, five-case fixture, unchanged exact graders and
manifest before provider output. Verify the stopped parent report/journal/
failed-replay byte hashes at launch. New deterministic seeds give two Boolean
entailment cases at level 4 and one each of SQL bag semantics at level 7,
event replay at level 6 and scoped source selection at level 6. References
stay evaluator-only; the authored fixture is public. Use the five cyclic arm
orders in the manifest, matched session IDs/RNG/logical clocks and independent
provider samples. No case regeneration, replacement or score-driven prompt
change during this frozen study.

All native arms use explicit left lead, manual System2 ON, task goals AUTO,
completion replanning AUTO, balanced AUTO gates, Director/executive OFF,
work products OFF and no ordinary continuation. Draft/integration caps are
4096, critic/repair caps 2048, ordinary-left total8192 and all-provider
per-trial output-ceiling allowance12288. The requested model is `gpt-6-luna`.
Native client timeout120s is identical across arms. Only ordinary draft and
integration requests receive the chosen reasoning-effort profile; external
critic requests retain provider default.

1. `default_off`: provider-default ordinary effort and completion-aware critic
   OFF. This is the primary native baseline.
2. `default_aware`: provider-default effort and completion-aware critic ON,
   separating critic routing from effort.
3. `medium_aware`: medium ordinary effort, completion-aware critic ON.
4. `low_aware`: low ordinary effort, completion-aware critic ON.
5. `self_review`: existing four-stage reference with caps4096/2048/4096/2048,
   existing 60s stage timeout and provider-default effort. It is contextual,
   not a one-variable causal comparison with the native arms.

Require `SSL_CERT_FILE=certifi.where()` and at least 100 certificates in the
default Python SSL context before live admission. This is local preflight, not
a provider health request. Assert every serialized cap and effort parameter
before or at admission; unknown role/cap/effort closes the study as
configuration-invalid. At most 96 conservative admissions across the 25
cells. Reserve full caps without refund for failures/cancellations. Stop
future paid work on genuine or unclassified transport/auth/quota/provider
failure. No paid judge, health call, rescue, retry, new model or outcome-driven
follow-up in this frozen study. Attempted requests without usage receipts
remain unknown; do not estimate full token totals or billing.

Use the frozen exhaustive Boolean, evaluator-authored SQLite/Python,
event-state and source-scope graders. Preserve duplicate-key, whole-JSON,
schema and SQL bag rules. Count all 25 cells and unavailable outcomes.
Terminally complete returned answers keep semantic grades even when review
is unavailable. Report initial/final completion, exact and mean item scores,
all pairs, workflow validity, reasoning-token/visible-output receipts, actual
effort parameters, critic availability, admissions, reservations and missing
usage. If fewer than 25 cells finish, do not rank the full comparison.

A native profile is eligible for a later, separately frozen untouched holdout
only if its exact count exceeds `default_off` by at least one, its mean item
accuracy is no lower, and it has no lower per-case item score on SQL, events
or evidence. If both medium and low qualify, choose medium unless low has a
strictly higher exact count and no lower item score on any case; if neither
qualifies, report a negative development result and revisit the mechanism on
new tasks. Do not tune these five results or promote a default from this
development screen.

Run one exact provider-network-forbidden replay at the frozen source. Preserve
recorded durations/admission order and actual owner cancellation. Require
full request/event coverage, canonical rows, grades, usage, reservations and
profile diagnostics. Keep failed replay evidence without tape fitting. Publish
filtered metrics and hashes; raw provider payloads/outputs stay private.
Independent samples and five authored tasks do not establish statistical
superiority or an isolated causal effect.
