# Luna draft-to-final results — 2026-11-27

With identical natural drafts and equal final-call limits, supplying the
standard Luna critic's issues doubled the number of fully repaired wrong
drafts from 3/8 to 6/8. It also increased the number of initially exact
drafts that ended wrong from 3/16 to 4/16. Final accuracy was 16/24 without
critique and 18/24 with it.

| Final generation | Wrong draft → exact final | Exact draft → wrong final | Exact final |
| --- | ---: | ---: | ---: |
| Without critique | 3/8 | 3/16 | 16/24 |
| With critique | 6/8 | 4/16 | 18/24 |

The [frozen protocol](critic-e2e-protocol.md) used 12 new authored tasks,
two fresh drafts per task, and provider-default reasoning effort throughout.
Each draft was shared by the two final generations. The comparison used
the native draft, external critic and integration methods. Each call had a
24-second ceiling and 4,096 completion tokens. Both finals received the
same instructions and prompt except for the collaborator note. Only valid
critique issues were forwarded. An ok review left both arms with the same
neutral note. The test used one critique and one final per arm, with the
full System2 controller outside the experimental path.

## Paired outcomes

| Initial draft | Both exact | Exact only with critique | Exact only without critique | Neither exact |
| --- | ---: | ---: | ---: | ---: |
| Wrong | 3 | 3 | 0 | 2 |
| Exact | 11 | 1 | 2 | 2 |
| Total | 14 | 4 | 2 | 4 |

All 24 critiques were structurally valid. The critic returned issues on
6/8 wrong drafts and 2/16 exact drafts. Issues reached the feedback arm in
all eight instances. All six flagged wrong drafts became exact with
critique, and three of those also became exact without it. Both exact
drafts that attracted false issues ended wrong in the feedback arm, one
also ending wrong in the control. Among the 16 rows with identical neutral
notes, each arm had one exclusive exact result. These rows demonstrate
sampling differences even with matched prompts.

| Domain | Initial exact | Final exact without critique | Final exact with critique |
| --- | ---: | ---: | ---: |
| Boolean logic | 4/6 | 6/6 | 4/6 |
| SQLite | 4/6 | 5/6 | 5/6 |
| Event state | 3/6 | 1/6 | 3/6 |
| Evidence authority | 5/6 | 4/6 | 6/6 |

The three repairs seen only in the feedback arm are event_slots_3 and
event_slots_2 (first samples) and evidence_scope_restore (second sample).
The two event critiques supplied the correct replacement fields, which the
final accepted. In the evidence case the critique mixed a good correction
to q4 with a false suggestion on q2. The final took the good correction and
kept the original correct q2.

The first entail_switch_matrix draft was entirely correct. The critic
misclassified q3 as always true, and the feedback final changed the right
answer to that wrong value. The control preserved the correct draft. On the
second sample of that same task both finals received the neutral note and
the feedback-track draw introduced a different error, on q4. On the second
event_slots_1 sample, both finals converged on the same wrong fields even
though the control did not see the misleading critique. These cases distinguish
an observed adoption of a false critique from a regression also seen
under independent rewriting.

All 96 calls completed within their time ceilings and returned usage.
All drafts and finals were terminally complete JSON of the requested shape.
Total usage was 71,654 input and 63,394 output tokens. Stage durations were
observed in concurrent waves. The control also waited for the critic before
the matched finals launched, so these timings do not represent deployment
latency for the route without a critic.
