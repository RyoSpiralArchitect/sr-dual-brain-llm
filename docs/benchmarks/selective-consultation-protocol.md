# Selective conversation consultation protocol — 2026-11-01 (Asia/Tokyo)

Commit the router, fixture, runner and rubric before any provider calls. Develop
on two trials only, then freeze production code and run the eight evaluation
trials once. Do not tune on evaluation answers or regenerate favorable answers.

This is a frozen-draft routing mechanism study in fresh production EngineSessions,
not a new PostgreSQL/restart study or an estimate of natural error frequency.
For model-origin trials, one real clamped left-only turn produces a shared draft
using the production memory context and support checker. Capture that initial
draft unchanged. Synthetic clean/faulty variants are authored counterfactuals;
report them separately from model drafts. All arms receive exactly the same draft
and primary records. Ground-truth references and rubric enter grading only.

Arms: unchanged draft (zero post-draft calls), existing auto routing, selective
auto routing, and forced System2 on. Actual controller draft generation is replaced
with the frozen text for the latter three arms; subsequent support, critique,
revision and verification use production paths and live clients. All are
left-led, executive/director off, conversation mode on, balanced System2 priority,
round-target minimum zero. Preserve every normal component and fallback guard.
The selective flag is enabled only for its own arm. It is opt-in in the product.
No embeddings or environment-selected support backend is allowed.

Fresh in-process sessions isolate arms; RNG/UUID/time sources are controlled as
in the persistent-answer pilot, with Torch policy initialization seeded if present.
Do not claim independent fresh OS processes or database durability here. Trials
are shuffled with seed 20261101. The three processing-arm orders rotate/reverse;
positions are approximately balanced, not a repeated latency experiment.

The authored evaluation has eight trials but six distinct problems: four model-
draft problems and two paired synthetic clean/faulty problems. Declared project
version numbers deliberately exercise the distinction between identifier digits
and arithmetic. This stratified sample is not representative traffic. Synthetic
repair rates cannot be interpreted as naturally occurring quality improvements.

The router is a model-free estimate, not a factual verifier. It may skip only a
bounded lookup with one currently approved numeric record, a uniquely resolved
reference, sufficient numeric coverage, no new numeric claim, high heuristic
confidence and no risk signal. Qualitative-only, missing, ambiguous, multiple or
incomplete evidence defers to existing routing. Explicit review/reasoning and
numeric drift request critique. Explicit modes/leads, precision priority, source
writes, director decisions and ACC overrides retain their authority. Source
status and support approvals never change. Confidence is the existing heuristic,
not a calibrated provider confidence. Matching numbers cannot prove semantic
correctness; leave the feature opt-in pending broader quality evidence.

Use generation/support gpt-6-luna and a separate blind gpt-6-sol judge. Reuse the
prospective task/grounding/clarification rubric and atomic JSON-schema/literal-
quote validation. Shuffle labels and grade all four arms together per trial.
Count every packet failure and uncertain grade, and retain unavailable generation.
No scoring retries, partial salvage or subset evaluation. Report model and
synthetic strata, clean-draft harm and faulty-draft repair; never use internal
critic issue counts as independent answer correctness.

Budgets for this new experiment: at most 64 development calls and 160 evaluation
calls, 224 total. This is separate from the completed persistent-answer budget.
Journal all POSTs by role, including shared drafting/support and grading; abort
generation on a provider failure and block further transport after the first
failure. Missing usage remains unknown. Requested output caps are 2048 for
draft/left/judge, 520 for right critique and 4096 for support. No continuations or
automatic retries. Unused calls are not permission to resample.

Report per-arm post-draft costs separately from shared draft creation and judge
costs. Include actual token usage, calls and outer handler wall time. The zero-
call unchanged-draft arm has zero processing time; do not present it as an
end-to-end latency. Session creation/hydration is outside handler timing. Frozen
draft generation is shared once, so arm costs are not full independent production
turn costs. Timing is descriptive only. Match exact full-request replay with zero
provider calls; preserve failures, policy/fixture/revision/request hashes and
actual configured/served models. Raw drafts, responses, quotes and journals stay
private in ignored target/benchmarks; publish only metrics and hashes.
