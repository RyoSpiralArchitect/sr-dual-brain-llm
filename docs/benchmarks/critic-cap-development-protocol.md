# Critic-cap recovery: adaptive prospective native development screen

The preceding [reasoning-profile screen](reasoning-profile-development-2026-11-14.md)
stopped after one Boolean case. Low ordinary effort made a complete but
semantically wrong answer available; its 2048-token external critic returned
empty. A separate self-review request failed with `ClientOSError`, as in the
earlier frontload screen. This follow-up therefore tests an **adaptive
hypothesis** on new questions: whether allocating 4096 rather than 2048
completion tokens to the external critic makes low-effort answers reviewable
and improves exact outcomes. Omitting the self-review reference avoids the
observed transport blocker. Neither stopped study provides a full ranking.

Freeze source, this protocol, five-case fixture, unchanged exact graders and
manifest before any provider output. At launch, verify byte hashes and state
of the stopped parent report, journal, failed replay report and failure
marker. The five deterministic fresh seeds generate two Boolean entailment
cases at level 4 and one each of SQL bag semantics at level 7, event replay
at level 6 and scoped source selection at level 6. No question repeats a
prior study. The public fixture includes evaluator-only references; provider
payloads and outputs remain private. Use the five cyclic arm orders in the
manifest, matched session IDs/RNG/logical clocks and independent provider
samples. Do not replace tasks, alter scoring or tune prompts during this run.

All arms use explicit left lead, manual System2 ON, task goals AUTO,
completion replanning AUTO, balanced AUTO gates, Director/executive OFF,
work products OFF and no ordinary continuation. Draft/integration caps are
4096 each, ordinary-left allowance 8192, all-provider per-trial output
ceiling12288, requested model `gpt-6-luna` and native client timeout120s.
Only draft and integration requests use an explicit ordinary effort; critic
requests retain provider-default effort. Critic JSON repair, if admitted,
uses that arm's critic cap and remains inside the trial ceiling.

1. `default_off`: provider-default ordinary effort, completion-aware critic
   OFF, critic cap2048. Primary native baseline.
2. `default_aware`: provider-default ordinary effort, completion-aware critic
   ON, critic cap2048. Routing control.
3. `low_aware`: low ordinary effort, completion-aware critic ON, critic
   cap2048. Low-effort control.
4. `low_critic4096`: low ordinary effort, completion-aware critic ON, critic
   cap4096. New mechanism candidate using an existing configuration knob.

Require `SSL_CERT_FILE=certifi.where()` and at least 100 certificates in the
default Python SSL context before live admission. This local preflight is not
a provider health request. Assert serialized caps and effort at admission;
unknown role/cap/effort makes the study configuration-invalid. At most 80
conservative admissions across 20 cells. Reserve full caps without refund
for failures/cancellations. Stop future paid work after genuine or unclassified
transport, authentication, quota or provider failure. No retry, rescue,
paid judge, health call, model switch or outcome-driven change in this frozen
run. An attempted call without usage remains unknown, not zero.

Use the frozen exhaustive Boolean, evaluator-authored SQLite/Python,
event-state and source-scope graders. Preserve duplicate-key, whole-JSON,
schema and SQL bag rules. Report all 20 cells or mark unmeasured cells;
report initial/final completion, exact and mean item accuracy, paired deltas,
workflow validity, critic review validity, reasoning/visible-output receipts,
actual cap/effort parameters, admissions, reservations and missing usage.
Terminally complete answers retain their semantic grade even if review is
unavailable. Fewer than 20 cells cannot establish a full ranking.

The cap candidate qualifies for a later separately frozen untouched holdout
only if all 20 cells finish, its exact count exceeds `default_off` by at least
one, its mean item accuracy is no lower, it has no lower item score on any
SQL/events/evidence case, its workflow-valid count is no lower than
`low_aware`, and it yields at least one more valid external critic review
than `low_aware`. An available but incorrect answer or a valid review alone
does not qualify. If these gates fail, report the negative development result.
Do not promote defaults on this adaptive screen.

Run one exact provider-network-forbidden replay at frozen source, preserving
recorded durations/admission order and actual owner cancellation. Require
full request/event coverage, canonical rows, grades, usage and reservations.
Keep any failed replay evidence without tape fitting. Publish filtered
metrics and receipt hashes. Independent provider samples and five authored
tasks cannot establish statistical superiority or isolated causal effect.
