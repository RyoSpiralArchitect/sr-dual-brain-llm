# Fixed mixed critique and draft retention results — 2026-11-27

The verifier kept 22 of 24 correct fixes and blocked all 32 damaging
suggestions. It kept the correct fix and blocked the damaging suggestion
together in 22 of 24 mixed trials. Returning the draft unchanged would
have saved ten final generations and forgone two repairs in this cohort.

The [fixed protocol](fixed-mixed-claim-protocol.md) ran 12 mixed cases and
four correct-draft controls twice each with standard gpt-6-luna. Each
mixed critique had one correct repair for a wrong field and a damaging
change to a correct field. Each control had one damaging change. The
verifier saw only the question and target field names. This study used
fixed drafts and critiques without a live draft generator or critic.

## Verification outcomes

| Frozen opportunities | Passed to integration | Blocked by independent disagreement | Blocked because the response was invalid |
| --- | ---: | ---: | ---: |
| Correct repair within mixed critique | 22/24 | 0 | 2 |
| Damaging suggestion within mixed critique | 0/24 | 22 | 2 |
| Damaging suggestion on exact control draft | 0/8 | 8 | 0 |

All 52 usable independent field values matched the oracle. The two
invalid responses were both second samples from the event domain
(event_snapshot_overwrite and event_snapshot_no_alias). Each produced a
complete JSON object followed by an extra model marker. The frozen
parser rejected the entire response. An after-run inspection of the
JSON prefixes found the correct values and valid quotations in both
cases. The original scores and routing decisions retain the failures.

## What happens after no suggestions pass

The unfiltered and verified regeneration arms both scored 32/32 exact.
The integration model independently avoided all harmful suggestions and
repaired every wrong draft in this fixture, including the two trials
where verified regeneration received a neutral note. On the 22 nonzero
trials, retention shares the exact same verified regeneration output.
Its differences therefore come only from the ten zero-pass trials.

| Initial draft and reason for zero pass | Trials | Exact after neutral regeneration | Exact when returning the draft | Final calls avoided by retention |
| --- | ---: | ---: | ---: | ---: |
| Exact, all harmful suggestions rejected by verification | 8 | 8/8 | 8/8 | 8 |
| Wrong, verifier response invalid | 2 | 2/2 | 0/2 | 2 |
| All zero-pass trials | 10 | 10/10 | 8/10 | 10 |

All ten retention outputs match the original draft byte for byte, and
the retention branch made no final admission. The benchmark still ran
neutral regeneration as the measured counterfactual. This saved-call
policy would have avoided the observed 5,181 input and 762 output
tokens from those ten final calls. Verification costs still apply.

Every exact control stayed exact even after regeneration, so this run
observed no correctness advantage from retention on those controls.
The two missed repairs came from wrong drafts with unusable verification
responses. That gives a concrete reason to track a valid rejection
separately from a failed verification format. There were no wrong
drafts with valid verification that rejected every proposal in this
cohort.

## Reproducibility

All 96 physical calls completed within the 24-second ceilings and had
usage receipts. Every call used the 4,096 completion-token limit and
provider-default effort. The matched final prompts differed only in the
collaborator note. The received verification prompts contained no draft,
proposed values, or oracle. The native integration produced 64 terminally
complete and exact JSON finals. Total observed usage across the physical
calls was 52,554 input and 26,081 output tokens.

Source and scoring were frozen at a9470e40eb77c9a8f82702589c74b75fc72cf535.
The fixture regenerated byte for byte from the synthetic oracle script.
The independent audit checked all 96 admissions, returned grades,
citations, and both retention routes. Scoring recomputed byte for byte
with network access blocked.
