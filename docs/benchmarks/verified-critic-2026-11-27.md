# Luna claim verification results — 2026-11-27

The verified condition missed the predeclared criterion. It matched the
standard critic's one repair and lost three initially correct drafts.
The standard condition lost zero. The verifier rejected seven of nine
incorrect suggestions and admitted two. Neither admitted suggestion
changed a final answer to the proposed wrong value.

The [frozen protocol](verified-critic-protocol.md) used 12 new tasks and two
natural drafts per task. All three final calls shared the same question,
draft and integration prompt. The two critique conditions used the same
native critique and field-patch format. Verification had access to the
question and requested field names, without the draft, proposed values or
oracle. A proposal passed when a fresh standard Luna response derived the
same typed value and cited exact excerpts of question lines. The only
difference visible in a final prompt was its collaborator note.

## What passed the gate

All 24 native reviews were valid. Three exact drafts drew a total of
nine eligible proposals. Every proposal would have changed a correct field
to a wrong value. Verification disagreed with seven and independently
produced the same wrong value on two. In event_priority_queue, sample 1,
the two accepted changes concerned the final pick and the invalid-action
count. The verifier cited real event lines while missing a relevant expiry
and a failed operation. All three final answers still preserved the right
values.

Both wrong drafts received an ok review. The SQLite draft was repaired in
all three conditions and the event ledger draft remained wrong in all
three. There were three wrong fields across the two drafts, and the critic
proposed zero correct fixes. The final repair counts show no difference
in this cohort. There were no correct suggestions with which to estimate
the gate's ability to retain them.

The verified arm's three wrong finals all followed a neutral note. In
source_group_inheritance sample 1 and event_priority_queue sample 2, the
standard arm also received the same neutral note and preserved the correct
draft. In logic_knot_groups sample 2, verification rejected two false
proposals concerning group and pivot. The verified final changed the
unrelated tails value to a wrong answer. The control, which received the
same neutral note as the verified arm, preserved that value. The observed
three-case gap includes independent rewriting variation.

This run shows that the current check can screen out incorrect suggestions,
while matching values and quotes do not guarantee a correct derivation.
It provides no observed reduction in final regressions. The two wrong
drafts and three trials with different notes leave little information about
repair under verified advice.

## Usage and verification

All 123 admitted calls completed within their limits and had usage
receipts. The three verifier calls took 9.78–12.34 seconds each and
accounted for 2,069 input and 4,709 output tokens. Across the entire study
there were 86,131 input and 68,059 output tokens. Those counts include a
single shared draft per triplet. Calls ran in concurrent waves.

The study ran from frozen commit e82a40889bc6ce9e9cf580b75c57f4f8a5c8b6a6.
Oracles regenerated byte for byte from truth tables, SQLite and state
simulation. All 123 requests were checked against the frozen limits and
roles. Matching draft text, question and final system prompt were checked
for every triplet. The recorded scores recomputed exactly with network
access blocked and were independently checked against the raw answers.
