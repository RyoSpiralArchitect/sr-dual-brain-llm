Freeze this protocol, `constraint_mixed_comparison.json`, runner/tests and clean
source revision before any paid output. One ten-pair pilot, no paid health probe,

inputs. These new synthetic questions/references are authored by the implementing
assistant, without independent human calibration.

Use the current runtime for both conditions. `witnesses` retains the production
local checker. The benchmark-only `ablated` condition makes exactly the micro-
critic entry to `check_constraints` return an empty `CheckReport`; legacy micro
checks, ordinary model critic, source/literal guards, state cleanup, TRN and
ordinary routing remain. No model response, draft, policy action, critic verdict
or requested effort is substituted. Drain/close each fresh session before
restoring the detector function. This is an availability ablation, not a new
production flag and not a historical whole-runtime comparison.

Ten fresh problems: two numeric (one affine with withdrawn assumptions, one
unsupported nonlinear ambiguity), two JSON (one unconditional record, one
inactive conditional key directive), two code, one SQL, one evidence/uncertainty,
one prose and one byte-exact transcription. Negative controls are nonlinear,
conditional JSON and literal transcription. Use the fixed case order, balanced
arm order and balanced blind labels in the fixture. Manual System2 is OFF for
prose/transcription, AUTO otherwise; preserve native policy in all turns. Goals
are AUTO in both arms, other balanced AUTO gates retain the existing profile,
Director/executive are OFF. These are study settings, not default promotion.

Use fresh in-memory sessions, no primary seed/external persistence, the same
per-case session ID, question/QID, clock and RNG initialization in both arms.
Native generated drafts and downstream samples remain independent; a difference
in one pair is not an isolated causal proof of checker benefit. Fingerprint the
first runtime provider request without the arm's journal label, and retain any
input mismatch. Do not force matching later requests after different responses.
