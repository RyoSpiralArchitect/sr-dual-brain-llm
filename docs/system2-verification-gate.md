# System2 critic verification gate

System2 uses a right-brain critic to find issues in a draft, a left-brain
revision, and (when budget permits) another critic pass. The critic's issue
count is generated by a model. A zero count alone is insufficient to claim
that the reasoning is resolved.

The current gate marks a round `resolved` only when the critic is healthy, says
`verdict="ok"`, and returns no raw issues. It records a `resolution_basis` for
each round. A conflicting `ok` plus issues, `issues` plus an empty list, an
invalid or missing verdict, or an unavailable/unstructured critic stays
unresolved. When verification has no issue list or clean verdict, the final
diagnostic issue count retains the prior count instead of becoming zero because
the response was empty. A filtered low-signal issue list may still have a
calibrated count of zero while the round remains unresolved. The benchmark
runner preserves that explicit unresolved signal.

This is a consistency gate for internal control and telemetry. It does not
validate the answer against an external ground truth, and an explicit clean
critic verdict can still be wrong. The next mechanism study should compare
issue-specific evidence and candidate answers against independently scored
outputs before adding any stronger promotion or rollback policy.
